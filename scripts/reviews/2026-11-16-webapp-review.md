## 1. ct-dose-estimator（最優先）

### A1 SSDE 換算係数表が原典と違う【確認済み】

原典: AAPM Report 204（https://www.aapm.org/pubs/reports/RPT_204.pdf）Table 1D（32 cm）・Table 2D（16 cm）、AAPM Report 293 Eq.1（頭部: f = 1.9852·exp(−0.0486·Dw)）。PDF を取得し pdftotext で表を取り出して照合した。

32 cm ファントム（`SSDE_TABLE_32`、`ct-dose-estimator/index.html:684`）

| 実効径 cm | ツール | AAPM 204 Table 1D | 比 |
|---|---|---|---|
| 8 | 3.04 | 2.76 | 1.10 |
| 16 | 1.90 | 2.06 | 0.92 |
| 20 | 1.50 | 1.78 | 0.84 |
| 24 | 1.19 | 1.53 | 0.78 |
| 28 | 0.94 | 1.32 | 0.71 |
| 32 | 0.75 | 1.14 | 0.66 |
| 36 | 0.59 | 0.99 | 0.60 |
| 40 | 0.47 | 0.85 | 0.55 |
| 44 | 0.37 | 0.74 | 0.50 |

22点すべてが不一致。46〜50 cm は原典の表（45 cm まで）に無い値。

16 cm ファントム（`SSDE_TABLE_16`、同 :690。コメントは「AAPM Report 293」）

| 径 cm | ツール | AAPM 204 Table 2D | AAPM 293 Eq.1 |
|---|---|---|---|
| 8 | 1.57 | 1.38 | 1.35 |
| 12 | 1.31 | 1.18 | 1.11 |
| 16 | 1.09 | 1.01 | 0.91 |
| 20 | 0.92 | 0.86 | 0.75 |
| 24 | 0.78 | 0.74 | 0.62 |

どちらの原典とも一致しない。頭部は SSDE を**高く**出す向き。

影響: ブラウザで「腹部-骨盤・AP 22 / LAT 32 cm（実効径 26.5）・CTDIvol 10 mGy」を入れると SSDE 10.3 mGy と出る。AAPM 204 では約 14.0 mGy。2026-03-27 の公開時からこの値。

直し方の候補:
- 32 cm は Table 1D の値（または同報告の指数式）に置き換える
- 頭部は Report 293 の式に置き換える。293 は水等価径が前提なので、AP×LAT からの実効径で代用するならその旨を書く
- eGFR・DRL のときと同じく、照合表を `scripts/` に置き、テストで表と原典値の一致を検査する
- 修正後、ページに訂正の告知を入れる（造影CTシミュレータと同じ扱い）

### A2 多相検査で DRL 判定が必ず厳しく出る【確認済み】

`recalculate()` は CTDIvol を1行目だけ、DLP を全シリーズの合計で DRL と比べる（:924-931）。DRL は「上腹部〜骨盤1相」など1相あたりの値。ブラウザで 2相（10 mGy / 500、12 mGy / 600）を入れると、どちらの相も 720 mGy·cm 以下なのに「DRL超過」と出た。2行目の CTDIvol 12 は判定に使われない。
→ 相ごとに判定するか、「合計 DLP は1相の DRL とは比べられない」と表示して判定から外す。要約カードの SSDE も1行目だけなので、同じ扱いにそろえる。

### A3 小児の k 係数とファントム径【確認済み（原典の注記）】

k 係数の値は AAPM Report 96 表3と一致した（頭部 0.011 / 0.0067 / 0.0040 / 0.0032 / 0.0021、腹部・骨盤 0.049 / 0.030 / 0.020 / 0.015 / 0.015 ほか）。ただし同表の注記は「成人の頭頸部と**小児**は 16 cm ファントム、それ以外は 32 cm ファントムを前提」。
- 小児腹部で装置が 32 cm 基準の DLP を表示している場合、この k を掛けると実効線量をおよそ半分に見積もる
- 一方でツールは小児腹部の SSDE を 32 cm 表で計算している（`REGIONS['ped-abdomen'].phantom = 32`）。同じ入力に対して k と SSDE で前提が食い違う
→ 小児を選んだときに「装置の表示が 16 cm 基準か 32 cm 基準か」を選ばせる。最低でも注意書きを出す。

### その他
- コードのコメントは「ICRP 103 / AAPM Report 96」だが、AAPM 96 の k は ICRP 60 の組織加重係数にもとづく値。ページ本文に k 係数の出典が書かれていないので、出典と「集団の目安で個人の線量ではない」ことを書く【要確認: ICRP の版】
- 小児は「小児DRLデータなし」と出るが、DRLs 2025 には小児 CT の DRL があり、drl-comparison は持っている
- 実効径が表の範囲外でも端の値をそのまま使う。範囲外と表示する
- シリーズ名を `innerHTML` にそのまま入れている（:946）。自分の入力だけなので実害は小さいが、エスケープする

## 2. mtf-calculator

### A4 MTF を低く出す【確認済み】

`computeMTF()`（:846）は、半径方向に1画素間隔で双線形補間して ESF を取り、角度方向に平均する。
- 双線形補間そのものがぼけを足す
- 1画素間隔の差分で LSF を作るが、その補正が無い
- 中心と半径が整数に丸められる（スライダー・自動検出とも）。ずれた分だけ角度平均でエッジがぼける

ページから関数を取り出し、既知のガウスぼけ（σ）を持つ合成円盤（画素 0.5 mm）で測った結果:

| σ（画素） | 中心ずれ | 50%MTF ツール / 理論 | 10%MTF ツール / 理論 |
|---|---|---|---|
| 1.5 | なし | 0.239 / 0.250（−4%） | 0.436 / 0.455 |
| 1.0 | なし | 0.337 / 0.375（−10%） | 0.616 / 0.683 |
| 1.0 | 0.4 画素 | 0.317 / 0.375（−15%） | 0.576 / 0.683 |
| 0.6 | なし | 0.483 / 0.625（−23%） | 0.847 / 1.138 |
| 0.6 | 0.4 画素 | 0.428 / 0.625（−32%） | 0.766 / 1.138 |

デモ画像でも自動検出の中心は (257, 257) で、作った中心 (256, 256) から1画素ずれた。
→ 円形エッジ法の通常の作り（各画素を中心からの距離で 0.1 画素幅などのビンに入れて、細かく刻んだ ESF を作る）に変える。中心は重心などで小数まで求める。合成画像での回帰テストを足す。task-based-iq の `computeTTF()`（:1215）も同じ作りなので同じ傾向が出るはず。

既知の課題（TIFF が Chromium で読めない）は未決のまま。

## 3. cnr-calculator / task-based-iq

### A5 NPWE の式【要確認】
`computeDetectabilityIndex()`（cnr :1642）と `computeDprime()`（task-based-iq :1326）は
d′ = ΔS·∫W²E² / √(∫W²E²·NPS)。
文献で一般的な NPWE は d′² = [∫W²·TTF²·E²]² / ∫W²·TTF²·E⁴·NPS で、分母の視覚フィルタは E⁴（+内部ノイズ項）。原著（Burgess 1994、Richard & Samei 2010 など）で確かめてから直す。

視覚フィルタ `E(f) = f^1.3·exp(−c·f²)`、c = 120 は f を cycles/mm のまま使っている。ピークは 0.074 cycles/mm。Burgess のフィルタは cycles/degree（ピーク 4 cycles/degree 付近）で定義されるので、観察距離と表示倍率による換算が要る。コメントの「c=120 は典型的」の根拠が見当たらない。
cnr-calculator の d′ には MTF / TTF が入っていない（小さい病変で高く出る）。その旨の記載も無い。

### A6 CNRlow と Rose 基準【確認済み（数式上）】
- CNRlow = コントラスト ÷ √(NPS の積分)。NPS の全周波数積分は分散なので、これは CNR と同じ量。しかも径方向の積分はナイキスト半径の外（四隅）を落とすため、白色ノイズなら √(π/4) ≈ 0.89 倍の SD になり、CNRlow は常に CNR より1割ほど大きく出る。「周波数特性を考慮した評価値」（:647）という説明と合わない。低コントラスト用の CNR として文献にあるのは、対象の大きさに応じた低周波帯の NPS で割る形
- 「Rose基準では CNR ≥ 3〜5 で検出可能」（:649）。Rose の基準は対象の面積で積算した SNR に対するもので、画素単位の CNR にそのまま当てると、大きい対象では厳しすぎ、小さい対象では甘すぎる

## 5. exposure-reference【要確認】
- グリッド係数（:526）は 5:1=2.5、6:1=3.0、8:1=3.5、10:1=4.5、12:1=5.5、16:1=6.0。出典に挙げた Bushong の表は 5:1=2、8:1=4、12:1=5、16:1=6 のはず。引用元と値をそろえるか、出典を変える
- プリセットの mAs は体幹部で高め（腰椎側面 90 kV・80 mAs、腹部 80 kV・25 mAs など）。管球出力を 0.06〜0.1 mGy/mAs（1 m）と置いた概算では、入射表面線量が DRLs 2025（腰椎側面 5.5 mGy、腹部 2.5 mGy 前後）の2倍以上になる。コードのコメントは「DR/FPD 想定」だが、値はフィルム・CR 時代の教科書に近い。出力の仮定に左右される概算なので、実測か文献値で確かめる。「代表値」と「DRL」を並べて見せると、このツールの価値が上がる

## 6. contrast-quick
- B3【確認済み】「ヨード注入速度（最大）」は希釈相を `r.cls === "ph-mix" ? 0.5 : 1` で計算（:950）。混合比を 50% 以外にすると、希釈相が最大のときに値がずれる。行に実際の混合比を持たせて使う
- 注入速度・総量に上限の注意が無い（例: 120 kg × 600 mgI/kg ÷ 300 mgI/mL = 240 mL でもそのまま表示）。シリンジ容量や施設の上限を超えたら注意を出す
- 総量⇔速度の切り替えで四捨五入が入り、500 → 16.7 → 501 mgI/kg のように値が動く
- 身長を消した状態で体表面積法に切り替えると、数値は kg 基準のまま単位だけ mgI/m² に変わる

## 7. mri-simulator
- B4【確認済み】FLAIR・STIR の TI を ln2·T1 で決めている（:770-771）。同じページの IR の式（TR 有限）では null 点は T1·ln(2/(1+e^(−TR/T1)))。FLAIR（TR 9000・CSF の T1 3500）なら 2168 ms で、プリセットの 2426 ms では CSF が約 7% 残る。プリセットを式の null 点にするか、説明に「TR が十分長いとき」と書く
- 緩和値は 1.5 T の教育用近似として妥当な範囲。信号方程式3本は正しい

## 8. nps-calculator
- NPS の正規化（Δx·Δy / (Nx·Ny)・|DFT|² の平均）は正しい
- 「2次多項式フィッティング」は、行平均と列平均をそれぞれ2次でフィットして引く近似（xy の項なし）。表示名か実装のどちらかをそろえる
- 画面の「NPS 積分の平方根」は四隅を落とすので SD より小さく出る（6 の A6 と同じ理由）。SD と並べるなら注記する
- ROI の SD は、ROI 間の平均の差を含まない（ROI ごとに平均を引く）。意図どおりならその旨を書く

## 9. DICOM 読み込み（5ツール共通）【確認済み】
`parseDicom` が5ツールで別々の実装になっている（5つとも中身が違う）。
- 圧縮 DICOM: cnr・brain-diff は「圧縮には対応していません」と出す。nps は「PixelDataが見つかりません」になる
- nps・cnr はメタ情報の読み取りを先頭 500 バイトで打ち切る（`offset < 500`）。メタ情報が長いファイルで、Implicit VR の本体を読み違える可能性がある。(0002,0000) の長さを使う
- 長さ未定義のシーケンスの中身を通常のタグとして読むので、アイコン画像（0088,0200）を持つファイルでは、アイコンの Rows / Columns / PixelData を本体と取り違えうる
- PixelData の長さと Rows×Columns の整合を確かめていない
→ 1つの `assets/dicom.js` にまとめ、合成 DICOM でのテストを付ける。実機の DICOM では今回確かめていない。

## 10. brain-diff【確認済み】
- `loadSeries()`（:960）は、渡されたファイルをすべて1本の体積にする。SeriesInstanceUID は読んでいるが、分ける処理に使っていない。マトリクスが同じ別シリーズが混ざるとそのまま通る
- ベースラインとフォローアップが同一患者か、検査日の前後が合っているかを確かめない。患者 ID を画面に出さずに一致だけを判定することはできる
- スライス枚数・スライス間隔の違いは互換性チェックの項目に無い
